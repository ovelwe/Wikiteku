# Жалобы и модерация статей

Опубликованная доступная статья → «Пожаловаться». Нужен вход. Причины: спам, травля, раскрытие личных данных, другое. Пояснение — 10–3000 символов, обычный текст. Снимок заголовка, аннотации, Markdown и ревизии записывается сервером; клиент не может подменить автора или содержимое снимка. Одна открытая жалоба пользователя на статью, максимум 10 новых в день UTC. Дубли не расходуют квоту.

Список собственных обращений: «Настройки» → «Мои обращения» (`/reports`), также мобильное меню. Доступ строго по ID текущего пользователя. Показанное решение относится к рассмотрению конкретной жалобы, а не является текущим статусом доступности статьи.

## Назначение модераторов

После миграции `0008_peaceful_bedlam.sql` оператор задаёт `PLATFORM_MODERATOR_IDS`: неизменяемые ID доверенных аккаунтов через запятую, затем перезапускает приложение. По умолчанию список пуст. Email, имя, роль владельца или администратора фандома не дают этих прав. Веб-интерфейс не позволяет назначить себя модератором. Переменная только серверная, без префикса `NEXT_PUBLIC_`.

У назначенного модератора появляется ссылка «Модерация» в настройках и на странице обращений. `/moderation` — очередь по 20 обращений, вкладки открытых и рассмотренных. `/moderation/[id]` — жалоба, исходный снимок, текущий текст и журнал по статье. Модератор платформы может рассмотреть сообщение о закрытой статье: это часть доверенных полномочий. Текст показан без выполнения Markdown/HTML и без загрузки внешних изображений.

Решение требует пояснения 10–1000 символов. Блокировка и снятие блокировки дополнительно подтверждаются флажком. Проверяются версия модерации и текущая ревизия текста. Конкурентное изменение даёт 409; нужно обновить страницу и прочитать актуальный текст. Решение и аудит сохраняются одной транзакцией; API изменения или удаления аудита нет.

## Поведение блокировки

Блокировка обратима и сохраняет текст, историю и оформление. Публичная статья отвечает 404 даже автору; её нет в поиске, sitemap, публичных списках/счётчиках, ленте и связанных материалах. Кэш перевода также недоступен. Редакторы фандома видят заблокированную статью в библиотеке, могут исправлять текст и работать с историей. Повторная публикация, восстановление из корзины или старой версии не снимают блокировку. При сохранении исправления редактор остаётся на форме с подтверждением.

Снятие блокировки доступно через рассмотренную жалобу с решением «заблокировать»; текущая версия проверяется заново. Другие ограничения сохраняются: снятие блокировки не публикует черновик, не возвращает архив и не открывает закрытый фандом.

## Ограничения

- Реализованы жалобы на статьи; нет блокировок аккаунтов/фандомов, вложений к жалобам, апелляций и уведомлений по почте.
- Самостоятельные адреса файлов продолжают наследовать видимость фандома. Блокировка статьи не удаляет медиа и не блокирует их URL; декоративные Puck-макеты не входят в снимок жалобы.
- Журнал сохраняется в БД без удаления через приложение, но не является криптографически защищённым хранилищем от оператора БД.
- Формы, сообщения и подписи доступны RU/EN. С 31 октября переведены также редактирование, история, настройки и медиатека; Studio остаётся русскоязычной.

## Локальная проверка

Используются только локальная `wikiteku`, синтетические аккаунты Phase 1 и тестовый фандом phase1-test. `node scripts/check-moderation.mjs setup` создаёт отдельную статью, сохраняет её ID и ID тестового модератора в `artifacts/moderation-fixture.json`. Передать этот ID как `PLATFORM_MODERATOR_IDS` только процессу тестового сервера; не записывать его в рабочие настройки.

С `DATABASE_URL`, `SMOKE_OWNER_PASSWORD`, `SMOKE_OUTSIDER_PASSWORD` выполнить `node scripts/check-moderation.mjs verify`. Скрипт проверяет права, ограничения, гонки и полный цикл блокировки/снятия. Временные статус и видимость тестовых объектов восстанавливаются, квота тестового читателя возвращается. Созданная статья, жалобы и аудит сохраняются. После теста перезапустить сервер без временного назначения модератора. Скриншот браузерной проверки: `artifacts/moderation-verified-20261030.png`.
